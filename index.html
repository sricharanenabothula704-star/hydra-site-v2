    The pipeline
    01 / 04

    RECON

    Maps the attack surface before anyone sends a packet. Passive sources first: certificate transparency, archives, passive DNS.

    • CDN-shielded hosts tagged, not scanned
    • Stops when two phases add under 5% new assets
    02 / 04

    HUNTER

    Probes entry points, runs the scanning pipeline and saves every lead instantly with a hash. Each lead is tagged UNVERIFIED.

    • Scope gate checked before any scan
    • Decision table for 403s, WAF blocks and silence
    03 / 04

    VERIFIER

    Tries to destroy each finding: baseline vs exploit requests, three replays, response diffing, false-positive checks.

    • ≥80% VERIFIED · 50–79% PARTIAL · <50% REJECTED
    • Rejections are logged with a written reason
    04 / 04

    REPORTER

    Writes a platform-style report: clear title, honest severity, working curl PoC with truncated proof, CWE and CVSS.

    • A human reproduces the bug before submitting
    • Impact stated in business terms

    PLAN · AUDITOR · DEBUG support every stage: research, code review and self-correction.

    Get started

    Two ways to install

    Use the terminal setup, or let an AI coding agent guide the setup from the repository. Full steps in the docs.

    1 · Terminal setup

    Clone and run bash setup.sh --handle YOUR_HANDLE --email you@example.com. An existing OpenCode config is backed up and replaced only after you approve.

    2 · AI setup prompt

    With OpenCode installed, open the repo as your workspace and paste the AI setup prompt. It explains the plan, backs up config, and runs setup after your approval. It does not launch a scan.

    Pick a model provider

    Launch OpenCode, use /connect to authenticate, then /models to select one. Cloud providers receive the prompts you send them. A local Ollama setup keeps prompts on your machine.

    Confirm your authorization

    Only test assets you own or have written authorization to assess. Add exact domains to ~/.config/opencode/SCOPE_ALLOWLIST.txt. The CLI and loop runner deny anything outside it.

    Hunt

    Launch opencode and use guarded CLI or loop commands. Direct agent commands and standalone scripts need your own scope review.

    Verify, then report

    Feed leads to /verify. Survivors go to /report, which drafts a writeup with reproducible PoCs. You review every claim before submitting.

    Evidence and limits

    What is checked, and what is not

    Automated checks

    CI runs Python compilation, index consistency, unit tests, scope-policy tests, frontmatter checks and a secret-pattern scan. These show basic integrity, not that every skill is correct.

    Scope boundary

    The CLI and loop runner gate supported commands against a local allowlist. Prompt instructions are not enforcement. Inspect standalone scripts before use.

    Known limitations

    No benchmark yet establishes precision or recall. Oracle checks are heuristics and may miss bugs or produce false positives.

    !

    Do not run the coordination server as shipped

    The optional coordination server binds to 0.0.0.0:5000 without authentication and serves submitted findings over HTTP. Keep it off, or bind it to localhost behind your own auth. The build agent also has shell and edit permissions. See Security & limits.

    FAQ

    Questions people actually ask

    Is this legal to use?
    Use it only on systems you own or have written authorization to test. The CLI and loop runner enforce the allowlist for their guarded commands. Standalone scripts may not, so inspect them and confirm scope before running anything that sends traffic.
    Will it find bugs fully automatically while I sleep?
    No. HYDRA automates recon, pattern matching, verification drudgery and report drafting. Choosing targets, reading business logic and deciding what is worth pursuing stays with you. Think of it as a fast junior team you direct.
    Do I need paid API keys?
    You need an AI model provider for model-backed workflows. Some offer free tiers, and a local Ollama setup keeps prompts on your machine. Cloud providers receive the prompts sent to them. Review provider terms and scripts before use.
    What makes this different from ChatGPT?
    A chatbot gives advice. HYDRA runs configured tools, keeps per-agent memory, applies a verification gate and drafts reports in platform format. It is a workflow with guards, not a chat window.
    Can it break my computer or leak my data?
    Findings are stored locally by default, which is not a guarantee that nothing leaves your machine. Do not run the coordination server as shipped (unauthenticated, 0.0.0.0:5000). Review scripts, permissions and provider data handling first.
    What if an agent gets stuck or hallucinates?
    Agents can get stuck or make mistakes. Treat every result as a candidate. Reproduce it independently, inspect the raw evidence, and review the report before anything is submitted.
